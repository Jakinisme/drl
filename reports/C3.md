## Graph

- input `obs` `float32[B,150]` (dynamic axis `B`), output `action` `float32[B,3]`,
  opset 17, IR 8, 10 nodes, 10 initializers. CPU only.
- deterministic mean: `action = tanh(mean_head(trunk((obs - obs_mean)/obs_std)))`;
  no sampling, no value head, no `log_std` in the graph.
- `PolicyNet` is **not** mutated: a thin `_Export(nn.Module)` holds `mean`/`std` buffers
  and reuses the checkpoint's own `trunk` / `mean_head` submodules, so the exported
  constants are the exact arrays training used (verified by the test, which reads the
  `(150,)` initializers back and compares to `policy.obs_mean/obs_std`).

### Normalization — one subtlety, read this before trusting `obs_offset`/`obs_scale`

`configs/env.yaml:obs.scale` normalizes the **raw 15-element** sample inside
`runtime/obs_np.py` *and* (the contract's obs builder) before the 150-value policy input;
the network therefore sees already-normalized, clipped ±5 values. The ONNX graph bakes
only `(obs - obs_mean)/obs_std`, i.e. exactly what `PolicyNet.forward` applies at
training time — identity for this checkpoint. `obs_offset`/`obs_scale`/`obs_clip_norm`
are still written into `policy_meta.json` from `configs/env.yaml` (15 floats each,
scale[0]=10.0, scale[6]=0.5, clip 5.0) because `runtime/policy.py` → `ObsBuilder` uses
them **before** the session call; they must not also be folded into the graph or the
normalization would be applied twice. Marked with a `ponytail:` comment in
`export_onnx.py`.

## Open issues / notes

1. `watchdog_s` (0.5) and the `safety.clip`/`rate_limit` duplication are fine today but
   have no single source: adding `runtime:` section to `configs/env.yaml` would let the
   export read all five safety values instead of two from config + one constant.
2. `torch.onnx.export(..., dynamo=False)` is pinned explicitly — torch 2.6's default
   exporter path has been moving, and the legacy tracer is what produces the small
   10-node graph above. Re-verify parity if torch is upgraded.
3. No recurrent state exists in `PolicyNet`, so there is no hidden-state I/O in the
   graph; `k_history` 10 lives entirely in the 150-element observation (history tiled by
   `ObsBuilder` on the Pi, not in the model).
4. The checkpoint's `obs_mean`/`obs_std` are identity, so "normalization baked in" is
   structurally present but numerically a no-op for this run. Re-export after any
   training run that populates them (set `obs_mean`/`obs_std` in `configs/train.yaml`).
