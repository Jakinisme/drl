## This is not yet a fair comparison — read before quoting it

The PID baseline **cannot close the loop in this sim**. Wave 3 measured that every body
command yields the same surge force (`[1,0,0]`, `[0,1,0]`, `[0,0,1]` all ≈ 19 N surge with
different sway/yaw coupling), so the heading loop saturates and limit-cycles. PID settling
0.0 % on `sk_wind` and `rough_sea` is that defect. The radial gap above therefore measures the
unmeasured thruster geometry (`thrusters.thrust_dir` / `positions_m`, SYSID B7/B8, INSPECTION
H6) as much as it measures the policy.

## Caveats

- Reward weights, geofence 80 m, arrival radius 2.0 m are placeholders (T7/T8).
- `obs.clip_norm` ±5 at a 10 m scale hides position errors beyond ~50 m.
- Episode counts below 8/8 are geofence truncations, not completions; `complete` flags it.
- `rough_sea` has only one seed — treat it as indicative, not a distribution.
- Env is CPU-synchronous (~80–180 ms/step at any batch size; `.item()`/`.cpu()` per step in
  `sim/disturbance.py` and `sim/sensors.py`).
- **Nothing here was validated against the real vessel.**

## Bugs found and fixed by the orchestrator

1. **`set_curriculum` takes a level INDEX, not a scale** (`envs/asv_env.py:234`). 
   `set_curriculum(1.0)` selects index 1 = **scale 0.1**. Fixed the two live call sites:
   `evaluate.py:check_fast_env` (both `AsvEnv` and `FastEnv`) and the misleading
   `train.py --curriculum-level` help text. The training run's auto-advance path is index-based
   and was never affected.
2. **`tests/test_evaluate.py` asserted the wrong thing.** `episode_arrays` right-aligns episode
   blocks per env, so `measured=1` takes each env's **last** block, not episode 0. Corrected the
   fixture to assert right-aligned semantics. `evaluate.py`'s logic was correct.

Also recorded, not fixed: `evalkit/plots.py:58` never closes figures (warns past 20 on a
3-scenario run); CONTRACT §4.8 still lists `gps_timeout_s`, which no runtime code reads.

## Provenance of the numbers

The full 3-scenario × 4-seed run was killed partway through a redundant re-run, so its console
log did not survive (it was overwritten by the re-run's first lines and is kept as
`reports/c2_eval_partial_rerun.log`). The per-seed `results/*_per_episode.csv` files from the
complete run all survived, and every figure in the table above is aggregated from those 133
rows — not reconstructed by hand. A later partial re-run reproduced `sk_wind` seed 0 at
PPO 11.10 m / PID 45.20 m, inside the aggregated per-seed ranges, so the run is repeatable.
