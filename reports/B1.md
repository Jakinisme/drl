## Layout (CONTRACT §5), 15 values per policy step

| idx | value | scale (divisor) | how computed |
|---|---|---|---|
| 0,1 | goal in body `dx, dy` [m] | 10.0 | `de*s + dn*c`, `de*c - dn*s`, `s,c = sin,cos(psi)` from `est` |
| 2,3 | `sin(psi_err)`, `cos(psi_err)` | 1.0 | `psi_err = wrap_pi(psi_goal - psi)` |
| 4,5,6 | `u, v, r` | 1.0, 1.0, 0.5 | estimator only (`est[:,3:6]`) |
| 7,8,9 | previous action | 1.0 | last **applied** (post rate-limit) action, zeros at reset |
| 10,11 | `wp1` body | 10.0 | next waypoint after the current goal, 0 if none |
| 12,13 | `wp2` body | 10.0 | the one after that, 0 if none |
| 14 | mode | 1.0 | 0 waypoint, 1 station keeping |

Normalize per step `clip((raw - offset)/scale, ±5)`, then K=10 oldest-first → 150.
`reset()` fills all 10 slots with the reset sample. In waypoint mode `psi_goal` = bearing
to the current goal (`atan2(de, dn)`, hull heading when within 0.5 m); in station keeping
`psi_goal` = initial hull heading, `wp1/wp2 = 0`.

Action in the obs is `a_{t-1}`, not `a_t`: the sample is built after the step with the
action that was applied *during* it, matching `runtime/policy.py` (`_last_action` set in
`_emit` at the end of the previous `step()`).

## Clock decision — `est["t"]` = control-loop monotonic time

`runtime/policy.py` (`_check`) faults `watchdog` when `now - est["t"] > watchdog_s`, with
`now = time.monotonic()` and `watchdog_s = 0.5`. Therefore **`est["t"]` is
`AsvEnv.t_loop`: seconds accumulated `+policy_dt` (0.1 s) per policy step, never reset per
episode, never derived from the GPS fix**. Verified in
`test_est_clock_is_control_loop_time` (exactly one `policy_dt` per step, a `reset()` does
not rewind it) and `test_est_clock_never_trips_the_runtime_watchdog`
(`0 <= now - est["t"] <= 0.5` for a 10-step loop). `get_estimator_state()` returns the
runtime dict (`lat, lon, heading_deg, yaw_rate_deg_s, speed_mps, course_deg, u, v, r,
gps_valid, sensor_ok, t`) with that same `t`; `info["time"]` and `info["t"]` are the same
number.

Why not a GPS timestamp: the fix is quantised to 5 Hz and delayed `latency_s = 0.2`, so a
fix-based clock is up to ~0.4 s stale at the moment the controller runs — already 80 % of
the 0.5 s watchdog budget, and any missed fix trips a false fallback to the PID.

## Reward (per policy step, all weights in `configs/env.yaml:reward`)

| term | formula | weight |
|---|---|---|
| position | `exp(-d / pos_sigma_m)`, `d` = distance to the current goal [m] | `w_position 1.0` |
| heading | `exp(-|psi_err| / head_sigma_rad)` | `w_heading 0.3` |
| progress | `clip((d_prev - d) / (max_surge_mps*policy_dt), -1, 1)` | `w_progress 0.5` |
| cross track | `-(min(xtrack/pos_sigma_m, 1))^2`, 0 in station keeping | `w_cross_track 0.2` |
| near-goal speed | `-(speed/max_surge)^2 * [d < slowdown_radius_m]` | `w_near_goal_speed 0.1` |
| action rate | `-mean((a - a_prev)^2)` | `w_action_rate 0.05` |
| energy | `-mean(a^2)` (normalized command², CONTRACT T7 open) | `w_energy 0.01` |

`pos_sigma_m 10.0`, `head_sigma_rad 0.5`. `xtrack` = distance to the current leg
(leg start = start pose / previous waypoint). Setting every `w_*` to 0 gives reward
exactly 0 (`test_reward_weights_all_come_from_config`): no hidden terms.

## Episodes, termination, curriculum

- `station_keeping_fraction 0.3` of envs hold a random point (uniform in
  `±waypoint_radius_m`), heading held at the initial hull heading, `n_wp = 0`.
- waypoint episodes: `n_wp ~ U[1,4]` waypoints uniform in `±waypoint_radius_m`; the goal
  advances when `d < arrival_radius_m` (2.0 m), `wp1/wp2` shift with it; after the last
  waypoint the goal stays and the hull is effectively asked to hold it.
- start pose uniform in `±spawn_radius_m`, `psi ~ U(-pi, pi)`, velocity 0.
- done = `ep_step >= max_steps` (1200 = 120 s × 10 Hz) or `|xy| > geofence_m` (80 m from
  the ENU origin). **Auto-reset** (`done` 1.0 = float32): the returned obs row is the
  post-reset sample, terminal state is only in `info` (`xy`, `goal_xy`, `psi`, `mode`,
  `dist`, `arrived`, `timeout`, `geofence`, `time`, `t`, `ep_step`).
- curriculum: level index auto-advances every `level_up_fraction * max_steps` (720 steps)
  from `start_level`, mapped through `disturbance.curriculum.scale_by_level`
  (`[0, 0.1, 0.25, 0.5, 0.75, 1.0]`) and pushed to `Disturbance.set_level`. Level 0 is
  exact zero disturbance (`test_curriculum_levels`). `set_curriculum(level)` pins the
  index (float) and disables auto-advance.

| quantity | range | mechanism |
|---|---|---|

## Issues found in existing code (reported, not fixed)

1. `sim/dynamics.py::set_params` accepts `mass_scale/inertia_scale/drag_scale` but casts
   them with `float()`, so it cannot take per-env tensors although its docstring says it is
   the env's randomisation hook. It also multiplies `D_lin[:2]`/`D_quad[:2]` by
   `mass_scale`. `envs/asv_env.py` therefore writes `M_env`/`D_lin_env`/`D_quad_env`
   directly (same tensors, documented in the module docstring). Suggested fix for A1:
   `torch.as_tensor(scale).reshape(-1, 1)`.
2. `sim/sensors.py` exposes no per-env hook for noise sigma or GPS latency (they are
   scalars), so those two knobs are drawn batch-wide at a full reset while the other
   randomisations are per env. Needs an A2 change if per-env noise is wanted.
3. `sim/thrusters.py::set_gains` mixes `slice(None)` and tensor indexing on `lag_tau` /
   `deadband`; passing a `[k]` or `[k,1]` tensor works (reshaped internally), passing a
   scalar fails. Works with what this env sends.
